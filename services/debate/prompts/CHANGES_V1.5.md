# 페르소나 프롬프트 V1.5 → 토론 실행기 적용본 변경 내역

V1.5 네 파일을 토론 실행기에 그대로 넣으면 출력 스키마·입력 형식과 어긋나 발언이 거절되거나 멈추는 부분이 있어, 아래만 고쳐서 `roles/<role>.md`로 넣었습니다. 문체·판단 원칙·섹션 번호(01~23)는 V1.5를 유지했습니다. **다음 버전은 이 수정본을 기준으로 고쳐 주세요.**

## 1. 역할 코드: intraday → market
- 실행기·DB·웹앱의 역할 코드는 `market`입니다. V1.5의 "역할 불일치 시 출력 중단" 규칙과 겹쳐 윤서연 발언이 전부 멈추게 됩니다.
- 네 파일의 팀 역할 문장, 다른 역할 제안 문장도 `market`으로 바꿨습니다.

## 2. 입력: role_payload 없음 → D_sources/S_sources로 설명 (01~05, 09, 22)
- 실행기는 `role_payload`를 보내지 않습니다. 역할별 자료는 근거 묶음에서 그 역할 몫만 골라 D_sources/S_sources로 보냅니다.
- 03절을 실제로 오는 지표 이름(metric_id)과 한국어 이름으로 다시 썼습니다.
- 09절에 D/S 항목의 필드(id, metric_id, label, value, unit, as_of, quality …)를 적었습니다.
- 22절: "필수 입력이 없으면 출력 중단"은 지킬 수 없습니다(출력이 JSON 스키마로 강제됨). 그래서 스키마대로 `insufficient_data` / `deferred`로 답하고, 화면 문장을 "지금은 판단에 필요한 최신 데이터가 충분하지 않습니다."로 시작하게 바꿨습니다.

## 3. 뉴스: N_sources 없음 → S_sources의 web_news (09, 16, 21)
- 뉴스는 별도 N_sources가 아니라 S_sources의 `kind=web_news`로 옵니다.
  - 서버가 웹 검색 결과를 AI로 요약하고 기사 날짜를 확인한 뒤 인용 링크를 붙인 것입니다.
  - verification_status가 없어서, V1.5의 "미확인 기사 제외" 규칙대로면 뉴스가 전부 버려집니다.
  - 대신 "확정 사실이 아니라 보도 내용으로 말하기('~라고 보도됐습니다')"로 바꿨습니다.
- `news_source_ids` 키는 스키마에 없어서 뺐습니다. 뉴스·공시 ID도 `rag_source_ids`에 넣습니다.
- 뉴스가 없을 때 쓰는 문장: "현재 확인된 최근 뉴스 요약이 없어 데이터 기준으로 설명드리겠습니다".

## 4. DART 공시 규칙 추가 (16)
- `kind=dart_disclosure`: 제목·접수일·제출인만 있고 본문은 없습니다. 제목만으로 내용·금액·주가 영향을 추정하지 않습니다.
- `metric_id=dart_detail`: 주요사항보고서 상세 항목입니다. 괄호 안 단위대로 읽고, 영문 약어 항목은 해석하지 않습니다.

## 5. 숫자 규칙 추가 (11, 14, 16)
- 화면 문장에 단위가 붙은 숫자(%, %p, bp, pt, 원)가 있으면 서버가 D_sources 값과 대조합니다. 맞지 않으면 발언을 공개하지 않습니다.
- 그래서 아래 숫자는 프롬프트에 있어도 답변에 옮기면 거절됩니다:
  - 11절의 지원 범위 통계(41구간, +58bp 등);
  - 14절의 연구 성능(81.9%, 13.96%p, 47.9%, 19.05%p);
  - 뉴스·공시 제목 속 숫자.
- 11절은 "드문 조건 / 관측된 적 없는 조합"처럼 말로만 설명하게 했습니다.
- 14절 성능 수치는 문장으로 바꿨습니다. ML 모델이 바뀌어 값이 달라질 수도 있습니다.
- D_sources에 없는 숫자를 모델이 직접 나누거나 더하지 않게 했습니다(비중·몫은 서버가 계산해 줌).
- 17절: 입력의 긴 소수(0.17221894…)를 그대로 옮기지 않도록 반올림 규칙을 넣었습니다. %·%p는 소수 둘째 자리, 비율은 %로 바꿔 소수 첫째 자리, 상관계수는 소수 둘째 자리까지 씁니다.

## 6. 포트폴리오: VaR/ES 미제공 기준 (강유나 02~05, 공통 15)
- ML에서 받는 포트폴리오 값은 두 개뿐입니다.
  - `holding_value_krw`: 전체 보유 금액, 원.
  - `center_pnl_krw`: 종목별 중심 손익의 합, 원, 손실은 음수.
- 다음 값은 **제공되지 않는 것으로** 정했습니다:
  - var95_krw, es95_krw;
  - es_contribution_krw, standalone_es95_krw, sum_standalone_es95_krw;
  - diversification_benefit_krw/pct.
- VaR/ES는 이 서비스 범위에서 뺐습니다. 답변에서 먼저 꺼내거나 "제공되지 않는다"고 매번 말하지 않고, 사용자가 직접 물을 때만 짧게 답합니다. 강유나는 대신 아래 근거로 위험 집중을 설명합니다.
  - 서버 계산: 종목별 보유 비중(holding_weight), 전체 손익 중 종목 몫(center_pnl_share), 전체 예상 수익률(portfolio_center_return).
  - 충격별 기여, 충격으로 달라진 수익률.
  - 장중 종목 간 상관·동반 하락 비율: "손익 합보다 꼬리 손실이 커질 수 있는 조건"으로만 씁니다.
  - 보유 종목 공시·뉴스.
- persona_data 키 `tail_contributions` → `pnl_contributions`로 바꿨습니다. ES 기여도가 없으므로 이름이 오해를 줍니다. 나머지 네 키는 V1.5 그대로입니다.

## 7. 출력 계약 맞춤 (20, 21)
- `ui_requests`: V1.5의 `{type, payload}` 대신 `{type, refs, role, reason}`입니다.
  - type은 OPEN_SOURCE_PANEL, SUGGEST_ROLE_TARGET, REQUIRE_CURRENT_DATA 셋뿐입니다.
  - OPEN_ANALYSIS_TAB은 앱에 없어서 뺐습니다.
- persona_data 키는 V1.5 다섯 키(문자열 배열)를 코드 스키마에 반영했습니다. 위 포트폴리오 한 키만 이름이 바뀝니다.

## 8. 구현 범위·고정 수치 갱신 (07, 12, 13, 14)
- 07절:
  - 커밋 해시와 "Gold 102,909행, 2000-01-04~2026-10-30"을 뺐습니다. 갱신마다 바뀌므로 기준일은 D_sources의 as_of로 보게 했습니다.
  - 운영 중인 것(장중 Eventhouse 연결, 4인 토론 실행기·API·하루 세 번 정시 회의, DART, 웹 뉴스)과 개발 중인 것(Stress Engine 연결, 포트폴리오 VaR/ES)을 현재 상태로 고쳤습니다.
- 12, 13절: 실제로 오는 항목에 맞췄습니다.
  - 일별 상태는 거시 역할에게만 오고, 종목 피처는 오지 않습니다.
  - 과거 유사 국면은 실제 수익률과 실제 충격만 오고, state_distance는 오지 않습니다.
- 14절: 모델 이름(LightGBM)을 뺐습니다. q10/q90 주의 규칙은 "제공되면" 기준으로 유지했습니다.
- 18절: 영문 지표명(metric_id) 대신 한국어 이름(label)을 쓰라는 문장을 추가했습니다. 검증기가 D1·S1 노출을 거절합니다.

## 9. 해석 일관성 (17)
- 테스트에서 리스크가 예상 수익률 -2.40%인 종목을 "방어적", +0.45%인 종목을 "하방 압력이 크다"로 묶고, 거시가 반론에서 충격 순위를 근거 없이 뒤집은 일이 있었습니다.
- 그래서 강·약 묶음과 순위는 어떤 지표 기준인지 밝히고 그 크기 순서를 따르게 했습니다. 충격 순위는 충격별 기여로만 말하고, 업종은 근거에 있을 때만 쓰게 했습니다.
- 단위는 근거의 unit을 그대로 쓰게 했습니다("VIX 0.00%" 같은 실수 방지, VIX는 pt).
- 근거 수치 없는 일반론("일반적으로 주식 전반에 부담")은 결론에 쓰지 않고 해석에서 가능성으로만 말하게 했습니다. 윤서연에게는 장중 관측 수치로만 판단하라는 규칙을 더했습니다(04절).

## 10. 파일 형식
- 파일 맨 앞 BOM은 실행기에서 제거하고 읽습니다. 메모장 저장도 괜찮습니다.
- 공통부(06~22)는 네 파일이 같습니다. 고칠 때 네 파일을 함께 고쳐 주세요.
- V1.5 문서에서 말한 테스트 JSON은 zip에 없었습니다. 실제 입력 예시가 필요하면 실행기 쪽에서 근거 묶음 예시를 드릴 수 있습니다.
