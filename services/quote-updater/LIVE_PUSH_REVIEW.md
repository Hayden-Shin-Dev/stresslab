# 실시간 화면 연결

기존 func-whatif-dev의 PostgreSQL 저장 로직을 유지하고, 처리 후 wps-whatif-dev로 체결을 전달합니다. 새 수집기나 Event Hubs 소비자 그룹은 만들지 않습니다.

브라우저는 quotes/negotiate에서 10분짜리 수신 전용 연결 주소를 발급받아 자동 연결합니다. 사용자 키 입력은 없습니다. 공개 테스트 화면이므로 접속자는 체결을 볼 수 있지만 메시지를 발행하거나 수집기를 조작할 수 없습니다.

Function 관리 ID에는 해당 Web PubSub 범위의 Web PubSub Service Owner 역할을 추가했습니다. CORS에는 기존 Static Web Apps 주소를 추가했습니다. Event Hubs, 키움 구독, 데이터 계약과 DB 테이블은 변경하지 않았습니다.

기존 배치는 최대 200건입니다. 웹 전송은 최대 50건씩 묶지만 각각의 체결 메시지를 유지합니다. 화면은 event_id 중복과 이전 시각 체결을 구분하고 종목별 최신값을 표시합니다. 전송 실패는 함수 실패로 처리되어 재처리될 수 있습니다. DB upsert는 유지되고 화면은 중복을 제거합니다.

화면은 연결 후 들어온 체결만 표시합니다. 연결 전 가격 조회와 끊긴 동안의 체결 복구는 포함하지 않습니다. 장 종료 후 새 체결이 없으면 빈 표일 수 있습니다. 실제 체결 수신과 인증 성공은 구분해서 검증합니다.

검증 코드는 tests/verify_live_push.py입니다. 저장된 체결 재생이나 합성 메시지는 보내지 않습니다. 실행 환경에는 requests, websockets, python-dateutil이 필요합니다.
