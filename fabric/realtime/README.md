# Realtime 작업 순서

키움 연결과 Event Hubs 전송은 수집 담당이 구현합니다. Realtime은 수신한 시세로 시장 상태를 분석합니다. 위험 감지는 분석 결과의 일부입니다.

| 단계 | 작업 | 폴더 |
| --- | --- | --- |
| 1. 시세 수신 | Event Hubs의 quote_event를 받고 원문을 보관합니다. | eventstreams |
| 2. 입력 검증 | 중복을 제거하고 공급자 시각, 수신시각, 거래 세션과 누락을 확인합니다. 미확인 자료는 구분합니다. | eventstreams, kql |
| 3. 분봉 생성 | 공급자 관측시각 기준으로 종목별 분봉을 만듭니다. 완료된 분만 분석하고 늦게 온 자료의 정정 이력을 남깁니다. | kql |
| 4. 시장 분석 | 장 시작 이후 흐름과 최근 구간의 수익률, 변동성, 거래량, 업종 등락, 하락 확산, 동조화를 계산합니다. | kql |
| 5. 서비스 전달 | 우선 1분마다 market_state_snapshot v2를 만들어 시장 상태 API로 전달합니다. UI와 AI가 같은 스냅샷을 사용합니다. | kql |
| 6. 마감 인계 | 원문, 분봉, 스냅샷을 저장하고 마감 후 누락·중복·정정 내역을 정리해 batch 담당에게 전달합니다. | notebooks |

## 계산과 전달 기준

종목·업종 정보와 전일 확정 종가는 batch 담당에게 받습니다. 분봉이나 비교 이력이 부족하면 해당 지표는 NULL로 두세요. 일부 종목을 코스피 전체로 표시하지 않습니다. 장중 지표는 확정 일별 ML 입력에 직접 넣지 않습니다.

[출력 계약](../../contracts/realtime/README.md)과 [Python 계산 참조](reference/)를 기준으로 구현하세요. Eventhouse와 Lakehouse 내부 테이블은 담당자가 설계하면 됩니다. Batch로 넘길 마감 자료의 위치, 거래일, 종목 범위, 품질 상태, 버전은 두 담당자가 맞추세요.

완료 기준은 같은 실제 분봉을 재생했을 때 참조 산식과 결과가 일치하고, 시세 변경이 API에 반영되며, 연결 끊김·지연·재수신 시 오래된 값이나 중복을 정상 값으로 처리하지 않는 상태입니다. 마감 자료를 batch가 읽는 것까지 확인하세요. 로컬 계산 검증과 Fabric 통합 검증은 별도입니다.
