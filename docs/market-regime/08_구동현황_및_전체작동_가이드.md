## 3. 프로젝트 전체를 작동시키는 방법

### 3.1 지금 바로 최신 결과로 갱신 (수동 1회, 약 8분)
1. Fabric → `ws-whatif-dev` → `MarketRegime` 폴더 → `PL_MarketRegime_Daily` 열기
2. 상단 **실행** 클릭
3. 왼쪽 **모니터링**에서 R01 → R02 → R03이 모두 "성공"인지 확인
4. `LH_MarketRegime` → Files → `regime/health.json`이 `ready`이고 `as_of`가 최신 거래일인지 확인
5. `RPT_MarketRegime`을 새로고침하면 새 기준일이 보임

**실행 전 확인:** 팀 Gold 파이프라인이 실행 중이면 끝난 뒤에 돌리세요. Gold가 준비되지 않았으면 R01이 `GOLD_NOT_READY`로 안전하게 멈추고, 이전 결과가 그대로 유지됩니다.

### 3.2 매일 자동 실행 켜기 (팀과 시각 합의 후)
1. `PL_MarketRegime_Daily` → 상단 **일정(Schedule)**
2. 시각 선택
   - 08:00 수집분 기준이면 **10:30 KST**
   - 12:00 수집분까지 반영하려면 **12:30 KST**
3. **켜기** → 적용
4. 다음 날 모니터링에서 자동 실행 성공을 확인합니다. 3일 연속 성공하면 운영 전환으로 봅니다.

### 3.3 서비스까지 연결 (다음 단계)
`12A_배포가이드_자동갱신_PostgreSQL경유.md`의 순서를 따릅니다: PostgreSQL 테이블 → 파이프라인 복사 활동 → 공통 API 경로 → APIM 등록 → 웹 메뉴.

### 3.4 멈추고 싶을 때
- 시장 국면만 멈춤: `PL_MarketRegime_Daily` 일정 끄기. 결과와 보고서는 마지막 값으로 남습니다.
- **Fabric 용량 일시 중지 주의:** Azure Portal의 Fabric 용량 `fcwhatifdev`(F2, Korea Central, 리소스 그룹 `5dt-final-team3`)에서 **일시 중지**를 누르면 **팀 전체** 노트북·파이프라인·보고서가 멈춥니다. 비용 절감 목적이라도 팀 합의 없이 누르지 마세요.

## 5. 라이선스·용량 주의

- 팀 워크스페이스 용량은 **F2**(Fabric 용량 `fcwhatifdev`)입니다. F2처럼 F64보다 작은 용량에서는 Power BI 보고서를 보는 사람마다 Pro(또는 PPU·개인 평가판) 라이선스가 필요합니다. 현재 Power BI 평가판이 끝나면 `RPT_MarketRegime` 열람이 막힐 수 있습니다.
- 서비스 사용자에게 보여 주는 화면은 Power BI가 아니라 **웹앱 팝업**(API 연결)으로 계획한 것도 이 때문입니다.
- F2는 계산 자원이 작습니다. 시장 국면 파이프라인(약 8분)이 팀 실시간 작업과 겹치면 느려질 수 있으므로, 장중보다 오전 수집 직후 시간대가 적당합니다.

## 6. 문제가 생겼을 때

| 증상 | 원인 | 조치 |
|---|---|---|
| R01 `GOLD_NOT_READY` | 팀 Gold가 갱신 중이거나 인증 해시 불일치 | 팀 Gold 완료 후 재실행. 데이터 손상 없음 |
| R01 `TEAM_LAKEHOUSE_DETECTED` | 노트북 기본 Lakehouse가 `lh_whatif`로 잡힘 | 기본 Lakehouse를 `LH_MarketRegime`으로 변경 |
| R03 게시 차단 (`health=blocked`) | 기준일 불일치, 이력 부족 등 | `health.json`의 사유 확인. 이전 정상 결과가 계속 서비스됨 |
| 보고서 기준일이 안 바뀜 | 파이프라인이 안 돌았거나 실패 | 모니터링 확인 → 수동 실행 |
| 보고서가 안 열림 | Power BI 라이선스·평가판 만료, 용량 일시 중지 | 5절 확인 |
