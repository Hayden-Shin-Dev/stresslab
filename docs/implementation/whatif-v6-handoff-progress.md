## 확인한 자료와 최신 실행 범위

`WHATIF_V6_CODEX_HANDOFF.zip`의 README, `01_IMPLEMENTATION_PROMPT.md`, `02_REFERENCE_GUIDE.md`를 읽고 K01/K02/K03/K09 참고 이미지를 열었다. 기존 작업 트리의 변경을 보존했고, a-uxui 스킬의 진단·구현·검증 흐름을 사용했다.

패키지는 별도 지시 없는 운영 배포·운영 DB 변경·실제 사용자 정보 삭제·원격 push/merge를 제한했다. 이후 사용자가 **배포를 승인**했으나 **DB 권한 변경은 허용하지 않았고**, 이어 **신규 삭제 기능을 취소**했다. 따라서 이번 적용 범위는 다음과 같다.

- **신규 계정·분석 결과·대화 영구 삭제의 화면, API, 실제 삭제 구현을 제거했다.** 단순히 숨기거나 비활성화한 기능이 아니다.
- 기존 보유 종목 삭제와 브라우저의 계산 요청 취소는 유지한다. 이 둘은 취소된 영구 삭제 기능과 구분한다.
- **DB 마이그레이션·GRANT·실제 데이터 삭제를 실행하지 않는다.** 실제 Entra 관리자 로그인과 DB 메타데이터 읽기는 성공했다.
- 운영 DB에는 `analysis_snapshot`, `user_workspace_settings`, `deleted_analysis`, `deleted_workspace_account`, `debate.revoked`가 없다. 기존 앱 역할에는 분석/대화 테이블의 새 DELETE 권한을 부여하지 않았다.
- 배포할 세 앱의 설정은 모두 **`WORKSPACE_STORAGE_ENABLED=false`**로 정했다. 기존 인증·보유 저장·스트레스 결과/AI 근거 저장·AI 요청을 유지하고, 새 보관소·실행 비교·서버 창 설정 동기화를 비활성화한다.
- 비활성화는 명시적 설정에 따른 동작이다. DB 오류를 무시하거나 허용되지 않은 저장소로 우회하지 않는다. `/api/me`의 `workspace_storage_enabled`, `workspace_storage_reason`으로 화면에 상태를 전달한다.
- 이 호환 모드는 삭제 표식 기능을 운영에서 한 번도 활성화하지 않은 DB에만 사용한다. 이미 삭제 표식을 사용하는 환경의 보호 기능을 해제하는 용도로 사용하면 안 된다.
- 공개 GitHub 푸시 없이 Azure 직접 배포 경로를 유지한다. 배포 성공 여부는 이미지 revision·APIM·웹의 실제 확인 후 기록한다.

## 구현 코드가 있으나 이번 배포에서 비활성화하는 기능

| 기능 | 비활성화 범위와 표시 |
|---|---|
| 새 결과 보관소 | `analysis_snapshot` 기반 수동/재실행 보관·상세·조건 불러오기. 새 DB 접근 권한을 추가하지 않으므로 비활성 상태 안내. 저장 성공으로 표시하지 않음 |
| 실행 결과 비교 | 보관된 2–4개 실행의 점·구간 그래프/표 및 별도 AI 비교. 보관소가 필요하므로 비활성. **현재 결과에서 최대 4종목을 비교하는 차트 기능은 유지** |
| 서버 창 설정 | `user_workspace_settings` 기반 revision 저장·복원 비활성. 현재 작업창 조작과 구분 |
| 비교 생성의 서버 취소 | 요청 취소 구현은 별도로 보존하지만 새 `revoked` 컬럼과 부분 출력 정리 권한이 없어 이 배포에서는 503. 브라우저 계산 취소를 서버의 AI 생성 중단 성공으로 표시하지 않음 |
| 유사 시장 국면 | 검증된 동결 모델과 인증된 독립 서비스 주소가 없어 제공 불가. 스트레스 계산이나 AI 응답으로 대체하지 않음 |

서버 서명 원본을 이용한 저장 재시도 코드도 남아 있지만, 보관소 UI의 재시도/복구를 이번 배포의 사용 가능한 기능으로 보고하지 않는다. 기존 결과 저장 성공과 새 보관소 비활성 상태를 분리한다.

## 파일과 API

프런트: `apps/web/quote-monitor/site/whatif-v6/index.html`, 기존 scenario-* 모듈, `assets/handoff-{runtime,archive,comparison,history,settings,windows,similarity}.js`, `handoff-{tokens,windows,common}.css`, `workspace-view.html`. `handoff-account.js`와 신규 영구 삭제 UI는 제거했다.

서버: `services/debate/src/{analysis_workspace,account_data,api,contracts,orchestrator,evidence,store,publisher,worker}.py`, `services/api/src/{gateway,analysis_context}.py`. `account_data.py`에는 기능 설정과 선택적 보호 확인 helper만 남으며 계정 데이터 영구 삭제 구현은 없다. 유사 국면 어댑터는 `analytics/src/conditional_service/similarity_api.py`다. 기존 엔진의 학습/계산 정의는 바꾸지 않았다.

다음 신규 경로는 **서버에서 제거했으며 APIM 추가 대상에서도 제외**한다.

- `GET /api/me/analyses/{run_id}/deletion-impact`
- `DELETE /api/me/analyses/{run_id}`
- `GET /api/me/account-data/deletion-impact`
- `DELETE /api/me/account-data`

기존 APIM operation ID는 보존하고 취소된 신규 ID 28·29·31·32는 건너뛴다. 기존 보유 종목 DELETE, DART/news 경로와 인증 정책은 유지하는 배포 계획이다. 운영 반영 완료 여부는 배포 결과 기록에서 별도 확인한다.

## DB 및 서비스 연결 전제

**이번 배포에는 SQL 실행이나 GRANT가 없다.** `services/debate/sql/analysis_workspace.sql` 및 관련 확장 스키마는 로컬 준비 파일이며 이번 운영 실행 목록에서 제외한다. 새 테이블과 `revoked` 컬럼을 읽지 않는 호환 모드로 공통 API·토론 API·worker를 함께 배포한다. 오류가 발생했을 때 동적으로 보호 검사를 우회하는 동작은 없다.

기본 활성 모드의 코드와 테스트는 남아 있다. 이후 새 보관소·서버 설정 기능을 활성화하려면 사용자와 범위를 다시 정하고 필요한 스키마·권한·호환성을 검증해야 한다. 취소된 영구 삭제 기능을 복원하는 것으로 해석하면 안 된다.

유사 국면 서비스는 기존 final_service의 SHA 검증을 통과한 동결 bundle을 필요로 한다. 현재 체크아웃에는 기본 `reports/service_scope_20261105/final_service_bundle.joblib`가 없다. 별도 인증된 서비스와 `SIMILAR_MARKET_API_URL`이 필요하며, 새 모델 학습이나 임의 artifact 생성은 하지 않았다.

차트의 분석 가격 컨텍스트는 실제 브라우저 관측값이며 거래소가 서명한 공식 종가라는 의미가 아니다. KRX/NXT 공식 장 마감·최종 종가 판정에 필요한 공급처 계약은 별도 확인 사항이다. 자동 보존 기간이나 자동 데이터 삭제 작업은 추가하지 않았다.
