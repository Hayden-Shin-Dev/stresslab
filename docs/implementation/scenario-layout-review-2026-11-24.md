# 시나리오 레이아웃·포트폴리오 작업창 검수

2026-11-24 요청: 나의 포트폴리오 자유 이동·크기 조절, KRDS 참고 레이아웃 진단 및 수정.

## 기준과 변경 범위

[KRDS 레이아웃 기준](https://www.krds.go.kr/html/site/style/style_05.html)을 참고했다. 유연하게 확장되는 작업 공간을 유지하면서 바깥 여백과 거터를 넓은 화면 24px, 작은 화면 16px로 정리하고, 내부 간격은 8px 단위를 사용했다. 1280px 미만에서는 한 열로 배치한다. 이 열 전환 기준은 이 화면의 차트·자료 패널 최소 가독 폭에 따른 구현 결정이며 KRDS가 모든 서비스에 강제하는 값은 아니다.

기존 색상·폰트 계열·실제 데이터·인증·저장 API·엔진은 변경하지 않았다. 차트 시계열, 모델 종점, 90% 상하방 구간의 계산과 의미도 유지한다. 보류 중인 DB 권한 변경과 취소된 신규 영구 삭제 기능을 다시 도입하지 않았다.

## 포트폴리오 조작

- `이동 창`을 누른 뒤 제목을 드래그해 이동한다. 오른쪽 아래 모서리로 크기를 조절한다.
- 제목에 키보드 초점을 두고 방향키로 이동, Shift+방향키로 크기를 조절한다.
- 기본 위치, 왼쪽/오른쪽 도킹, 최소화, 별도 창, 작업표시줄 복귀를 지원한다.
- 실시간 데이터 갱신과 전체 화면 렌더링 후에도 창 위치·크기·선택 탭·표 스크롤을 보존한다.
- 별도 창은 원본 상태를 공유하는 표시 창이다. 보유 종목과 분석 요청을 복제하거나 추가 저장하지 않는다.

## 검수 기록

1. **행동·상태 통과:** 이동/크기 조절, 최소화/복귀, 화면 크기 변경, 실시간 렌더링 중 상태 보존, 별도 창의 동일 상태 연결을 브라우저 fixture로 검증했다. 기존 모달의 클릭 차단기가 독립 창 이벤트까지 차단하던 오류도 수정했다.
2. **시각·접근성 통과:** 동일한 1440×1000, 1024×900, 390×844 화면을 전후 비교했다. 분석/포트폴리오 간격 24/16px, 차트 가림 해소, 채팅 입력창 접근, 가로 넘침을 확인했다. 320px 이동 창, 키보드 조작, 모바일 오른쪽 도킹, 작은 에이전트 창의 스크롤 접근도 통과했다. 긴 상태 메시지에서 입력창 하단이 잘리던 문제는 대화 영역 최소 높이와 스크롤 예외로 보완했다.
3. **회귀·데이터 통과:** 계산/단위/4종목 제한 등 기존 JavaScript 테스트 18개와 저장 비활성 모드의 분석·AI 연결 브라우저 회귀를 통과했다. 4종목 비교 fixture의 상단 +3%, 기준 +1%, 중심 -2%, 하단 -5%가 그래프/표에 일치하고 표시 변경이 추가 계산을 호출하지 않음을 확인했다. 포트폴리오 창 조작 중 보유 정보 변경이나 저장/분석 요청도 없었다. 브라우저 JavaScript 오류 0건, 배포 파일 구성 빌드 통과.

검증은 로컬 Chromium과 명시적인 테스트 응답으로 수행한다. 실제 운영 저장이나 실시간 API 성공을 새롭게 검증한 것으로 간주하지 않는다. 운영 배포와 운영 화면 확인은 별도 기록한다.

## 운영 배포 확인

2026-11-24 Azure Cloud Shell에서 공식 Static Web Apps CLI로 `swa-whatif-dev`의 production 환경에 직접 배포했다. 전체 정적 웹 파일 244개를 로컬 검수본 SHA-256과 대조한 후 별도 릴리스 디렉터리로 구성했다. CLI의 `Project deployed to https://red-field-0b8ece310.1.azurestaticapps.net` 성공과 릴리스 종료 표식 `WHATIF_CONTENT_LAYOUT_DEPLOYED_20261124`를 확인했다.

- 업로드 묶음 SHA-256: `3c810f4e0391872b66af9f4ca8f628cfcf2a8b10c5a991f74be0f22ab9f631dd`.
- 배포 산출물: `/tmp/whatif-content-layout-build`, 파일별 체크섬: `/tmp/whatif-layout-upload/sha256.json`.
- 비로그인 HTTP 검사는 `/whatif-v6/*` 인증 규칙에 따라 `/login.html`로 이동했다. 따라서 그 응답의 HTML/CSS 체크섬 불일치는 배포 실패로 판단하지 않는다. Azure가 소비하는 `staticwebapp.config.json` 자체는 공개 파일로 제공되지 않는다.
- 로그인된 Chrome에서 강력 새로고침 후 새 선형 창 아이콘, 포트폴리오 창 관리, `자료와 대화 높이 조절` 분할선, `분석 에이전트 · 4명 선택`, `상단에서 선택한 분석 에이전트에게 질문` 입력창을 확인했다. 기존 질문 대상 드롭다운은 없어졌다. 과거 시계열 245건과 기존 보유 목록·기존 에이전트 대화도 화면에 표시되었다.
- 운영 확인 중 새 스트레스 분석·질문 전송·보유 정보 변경은 실행하지 않았다. 높이 조절·역할별 POST·팝업·모바일 상세 동작 검증은 위의 로컬 브라우저 fixture 결과로 구분한다.
