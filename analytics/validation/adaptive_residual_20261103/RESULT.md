# 보정 기간 확대와 최근 잔차 갱신 검증

평균 전체 구간 폭 5%p 이하와 실제 포함률 80% 이상을 함께 달성한 방법은 없습니다. 보정 자료를 늘리면 포함률은 개선되지만 폭도 늘어났습니다. 최근 잔차 갱신도 이 문제를 해결하지 못했습니다. 운영 모델은 변경하지 않았습니다.

## 같은 조건에서 비교한 결과

Gold v1.1의 KRX, ECOS, FRED 데이터를 사용했습니다. 평가 시작일은 2023-01-02부터 2026-10-19까지입니다. 종목별 2,872개 표본과 삼성전자 및 현대차 각 50% 포트폴리오의 152개 평가 시점을 비교했습니다. 각 정답은 이후 5거래일 수익률입니다. 실제 발생한 거시 충격을 사후 조건으로 입력한 반응 재구성 평가이며, 충격의 발생 여부나 인과효과를 검증한 것은 아닙니다.

아래는 포트폴리오 결과입니다. 폭은 상한에서 하한을 뺀 전체 폭입니다. 기존 90% 구간과 혼동하지 않도록 이번 비교는 10~90 분위수인 명목 80% 구간을 기준으로 했습니다.

| 중심 모델과 구간 방식 | 평균 폭 | 실제 포함률 |
| --- | ---: | ---: |
| Ridge, 단순 변동성 80% 기준 | 12.21%p | 83.6% |
| Ridge, 1년 정규화 잔차 | 10.50%p | 73.0% |
| Ridge, 3년 정규화 잔차 | 10.85%p | 79.6% |
| Ridge, 5년 정규화 잔차 | 11.31%p | 81.6% |
| Ridge, 최근 3년 잔차 갱신 | 11.02%p | 79.6% |
| Ridge, 최근 5년 잔차 갱신 및 최근 자료 가중 | 11.28%p | 79.6% |
| LightGBM, 5년 정규화 잔차 | 11.10%p | 74.3% |
| XGBoost, 5년 정규화 잔차 | 11.29%p | 73.7% |
| LightGBM, 직접 분위수 회귀 | 8.88%p | 71.7% |

정규화 잔차는 각 과거 예측 오차를 당시 변동성으로 나누어 모은 뒤, 현재 변동성으로 환산한 값입니다. 정규화하지 않은 잔차 구간도 비교했으며 전체 결과는 metrics.csv에 있습니다. Ridge는 평균 수익률 회귀이고 나머지 중심 모델은 중앙값 회귀입니다.

개별 종목 전체에서는 5년 정규화 잔차 방식의 포함률이 Ridge 78.8%, LightGBM 79.1%, XGBoost 79.2%였습니다. 폭은 각각 14.48, 14.42, 14.57%p였습니다. 포트폴리오 결과를 개별 종목 성능으로 일반화할 수 없습니다.

## 보정 자료를 늘린 효과

포트폴리오 보정 표본은 평균 약 38개에서 115개, 192개로 늘었습니다. 최근 자료에 가중치를 준 방식은 평균 189개를 사용했지만 유효 표본 수는 약 103개였습니다. 표본 부족으로 이전 방식에 되돌아간 경우는 없었습니다.

Ridge의 5년 보정은 1년 보정보다 포함률이 8.55%p 개선됐지만 폭도 7.7% 늘었습니다. 날짜 10개 단위 블록을 1,000회 재표본추출한 포함률 개선의 95% 구간은 +4.61~+13.82%p였습니다.

단순 변동성 80% 기준과 비교하면 폭은 7.4% 줄었지만 포함률은 1.97%p 낮아졌습니다. 구간 점수는 16.94에서 16.69로 소폭 개선됐으나 차이의 95% 구간은 -0.71~+0.14로, 개선이 확실하다고 판단할 수 없습니다. 구간 점수는 폭과 구간 이탈을 함께 벌점으로 계산하며 낮을수록 좋습니다.

## 급락 포착은 여전히 부족합니다

KOSPI가 이후 5거래일에 5% 이상 하락한 평가 시점은 8개입니다. 아래는 그 시점에서 포트폴리오 실제 손실이 계산된 하한보다 더 컸던 횟수입니다.

| Ridge 구간 방식 | 하한보다 큰 손실을 놓친 횟수 |
| --- | ---: |
| 기존 변동성 90% 구간 | 1 / 8 |
| 변동성 80% 구간 | 3 / 8 |
| 1년 정규화 잔차 | 6 / 8 |
| 5년 정규화 잔차 | 4 / 8 |
| 최근 5년 갱신 및 가중 | 5 / 8 |

2026-10-08 시작 구간에서 실제 포트폴리오 수익률은 -10.80%였습니다. 5년 잔차 방식은 -8.49~+7.50%를 제시해 실제 손실을 2.31%p 과소평가했습니다. 1억원 기준 실제 손실은 약 1,080만원이고 제시한 하한은 약 849만원 손실이었습니다. failure_cases.csv에서 원래 계산값을 확인할 수 있습니다.

고변동성 평가 시점 51개에서 5년 잔차 방식과 변동성 80% 기준의 포함률은 모두 86.3%였지만, 하한을 넘은 손실 규모의 전체 시점 평균은 각각 0.105%p와 0.049%p였습니다. 포함률만 같다고 위험 포착이 같지는 않습니다. 급락 8개로 위기 전반의 성능이 입증된 것은 아닙니다.

## 왜 폭 5%p에 도달하지 못했는가

보정 표본 부족만의 문제는 아닙니다. 현재 중심 모델 자체의 오차가 남아 있습니다. 예를 들어 Ridge의 포트폴리오 중심값 오차는 평균 3.35%p였습니다. 중심값 양쪽에 2.5%p씩 붙여 전체 폭을 강제로 5%p로 만들면 실제 포함률은 46.7%였습니다. XGBoost도 47.4%였습니다.

이 계산은 원인 확인용이며 채택 후보가 아닙니다. 다른 데이터나 모델로 목표 달성이 불가능하다는 증거도 아닙니다. 다만 현재 모델의 보정 기간만 늘리는 것으로 좁고 신뢰할 만한 구간을 만들었다고 보고할 수는 없습니다. 표본 확대로 해결된 것은 잔차 분위수의 일부 과소보정이며, 중심값 설명력과 급락 오차는 해결되지 않았습니다.

## 미래 정보 관리와 남은 한계

1. 각 연도 모델은 직전 보정 연도보다 이전 자료로 학습했습니다. 학습 정답 종료일에 추가로 20일 여유를 두었습니다. 기준 모델과 같은 학습 경계를 유지했습니다.
2. 과거 잔차는 해당 시점 이전 자료로 학습한 모델에서 생성했습니다. 현재 모델이 학습했던 자료에 다시 예측해 만든 학습 잔차가 아닙니다. 여러 연도 모델의 외표본 오차를 모은 방식이라는 한계는 있습니다.
3. 최근 잔차는 5거래일 정답이 완성되고 20일이 더 지난 뒤의 예측에만 반영했습니다. 이전 예측값을 수정하지 않았습니다. 갱신 규칙과 모델 설정을 평가 성적에 맞춰 튜닝하지 않았습니다.
4. 보정과 평가 표본의 5거래일 정답 구간이 겹치지 않도록 처리했습니다. 모든 비교 방법의 평가 행, 모델 중심값, 기존 90% 기준 구간 재현을 확인했습니다.
5. 기존에 연구에 사용한 평가 기간이므로 독립 블라인드 검증이 아닙니다. 현재 Gold에는 과거 공표 시각과 수정 이력이 부족합니다. 20일 여유는 정답 중첩 방지 장치이지 당시 실제 데이터 이용 가능성을 완전히 입증하는 장치는 아닙니다.
6. 현재 선정된 20종목 기준이므로 생존 편향과 종목 선택 한계가 있습니다. 이 실험은 확정 일별 조건부 모델 B의 구간 비교이며 장중 분석 또는 전체 Azure 통합을 검증한 결과가 아닙니다.

목표 폭과 포함률을 함께 통과한 후보가 없어 최종 서비스 모델을 선정하지 않았습니다. 5년 잔차 방식은 연구 비교 대상으로 보존하며, 검증된 예상 손실로 승격하지 않습니다. Azure, 운영 모델, Gold 계약은 변경하지 않았습니다.

## 재실행과 자료

STRESSLAB_AUDIT_ROOT를 데이터가 있는 프로젝트 경로로 설정하세요. 해당 경로에는 exports/seongjin_gold_v1_1/gold_stress_daily.parquet와 이전 비교의 reports/oos_residual_intervals_20261103/predictions.parquet가 필요합니다. 원본 데이터는 저장소에 다시 올리지 않았습니다.

1. adaptive_residual_benchmark.py를 실행하면 세 모델의 보정 확대와 갱신 비교를 생성합니다.
2. direct80_comparison.py를 실행하면 직접 분위수 회귀 비교를 생성합니다.
3. finalize_adaptive_benchmark.py를 실행하면 두 결과를 합쳐 최종 지표와 블록 재표본추출 결과를 만듭니다.

metrics.csv는 전체 및 시장별 지표, paired_blocks.csv는 차이와 불확실성, sample_audit.csv는 연도별 표본 수입니다. portfolio_predictions.csv는 각 평가 시점의 실제 수익률과 구간 계산값입니다. center_precision.csv와 width5_subsets.csv는 사후 진단 자료이며 종목이나 시점을 골라 승인하는 용도로 사용하지 않습니다. verification.json과 protocol.json에 검증 항목과 평가 조건을 기록했습니다.
