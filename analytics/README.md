# 시장 분석과 조건부 스트레스 ML

이 폴더는 ML 담당자가 함께 작업하는 곳입니다. 학습과 검증은 Fabric Data Science에서 하고, 승인된 모델은 Container Apps의 Stress Engine에서 실행합니다.

## 무엇을 받나요?

Fabric에서 확정 일별 데이터인 `gold_stress_daily` 한 테이블을 받습니다. 종목별 가격, 코스피, 환율, 미국 금리, 한국 3년 금리, 유가, VIX와 관측 및 공개 시각이 들어갑니다. [컬럼과 전달 기준](../contracts/README.md)을 확인하세요.

키움 분봉은 현재 위험 표시와 포트폴리오 평가금액 갱신에 사용합니다. 장중 가격을 일별 종가처럼 넣어 ML을 다시 계산하지 않습니다.

## 무엇을 만드나요?

| 단계 | 입력 | 만드는 결과 |
| --- | --- | --- |
| 데이터 준비 | 확정 일별 가격과 거시 기록 | 기준일까지 공개된 값만 사용하는 학습 표 |
| A. 시장 검색 | 최근 확정 일별 시장 상태 | 비슷했던 과거 시장과 비교 근거. 사용자 충격은 사용하지 않습니다. |
| B. 조건부 ML | A와 같은 일별 상태 + 사용자 충격 | 종목별 5거래일 수익률 분포. 과거 사례의 실제 반응과 구분합니다. |
| 포트폴리오 계산 | 종목별 공동 수익률 표본 + 현재 보유금액 | 가상 손익, 손실 구간, 손실 기여도 |

시장 피처는 우선 코스피 20일 추세 및 변동성, 환율 20일 추세, VIX 수준, 미국 금리 수준, 유가 수준을 사용합니다. 자산별 최근 20일 및 60일 변동성은 손익 분포의 크기를 계산하는 데 사용합니다. ECOS 한국 3년 금리 수준과 20거래일 변화량(bp)도 비교 실험에 포함합니다. Gold의 korea_3y가 로컬 실험의 kr3y_level이며, kr3y_change20_bp는 `(korea_3y - 20거래일 전 korea_3y) × 100`입니다. 날짜별로 한 번 계산한 뒤 종목에 연결하세요. 종목이 반복된 행에서 shift(20)을 하면 안 됩니다. 계산식은 src에서 관리하고 학습과 서비스가 같은 코드를 사용합니다.

## 학습의 정답은 무엇인가요?

기준일 t와 5거래일 뒤 t+5의 가격으로 `100 × ln(종가[t+5] / 종가[t])`를 계산합니다. 화면에서는 일반 수익률로 변환합니다.

과거 학습에서는 같은 구간에 실제 관측된 충격을 조건으로 사용합니다. 환율 및 유가는 변화율 %, 미국 금리는 변화량 bp, VIX는 지수 차이입니다. 공급자의 실제 관측 구간도 기록하며 한국 종가와 완전히 같은 시각이라고 가정하지 않습니다.

서비스에서는 이 과거 충격 자리에 **사용자가 입력한 충격**이 들어갑니다. 예를 들어 환율 +5%는 5, 금리 +100bp는 100입니다. 미래 충격과 정답은 학습용이며 현재 시장 상태 피처에 섞으면 안 됩니다. 입력하지 않은 충격을 0으로 가정했다면 결과에도 표시합니다.

## 어떤 순서로 구현하나요?

1. src에서 종목별 학습 표를 만듭니다. 다른 종목의 결측 때문에 정상 종목까지 제외하지 않습니다.
2. 같은 확정 상태로 시장 검색과 조건부 ML을 연결합니다. 기존 Ridge(입력과 수익률의 관계를 학습하는 회귀 모델)는 비교 기준으로 유지합니다.
3. notebooks에서 학습합니다. 정답 구간과 공개 시각이 학습 기준일을 넘는 행은 사용하지 않습니다.
4. evaluation에서 같은 날짜 및 종목으로 변동성 기준 모델과 비교합니다. 손익 오차, 90% 구간의 포함률과 폭, 하위 손실 위험을 함께 확인합니다.
5. 검증을 통과한 모델과 전처리 및 피처 정의 및 지원 범위를 MLflow에 묶어 배포합니다. 현재 연구 모델은 정식 승인 상태가 아닙니다.

Ridge가 조건별 중심 수익률을 계산하고, 실제 반응과 모델 계산의 차이인 잔차를 붙여 여러 손익 표본을 만듭니다. 이 표본으로 손실 구간을 계산합니다.

종목별 최악 손실을 따로 뽑아 합치지 않습니다. 같은 날짜의 잔차를 함께 사용해 종목들이 동시에 움직인 관계를 보존합니다. 현재가가 바뀌면 금액을 다시 환산하지만 일별 모델의 손실률은 유지합니다.

| 폴더 | 작업 |
| --- | --- |
| src | 데이터 변환, 피처 및 정답 생성, 시장 검색, 추론, 손익 계산 |
| notebooks | Fabric 학습 실행과 MLflow 기록 |
| evaluation | 시간순 평가, 기준 모델 비교, 실패 사례 분석 |
| tests | 미래 정보 차단, 결측 처리, 단위와 손익 산식 검증 |

최근 표본 및 시각 수정에서 일부 개선은 있었지만 모든 종목의 성능이나 극단 충격의 신뢰성을 입증한 것은 아닙니다. 새 알고리즘을 추가하기 전에 이 데이터 정의와 동일 조건 비교를 유지합니다.

## Gold 완성 전 개발

성진님은 제공한 gold_stress_daily.parquet을 읽어 시작하시면 됩니다. 계약 v1.1과 같은 34개 컬럼이며 KRX, ECOS, FRED 실제 관측값입니다. 생성 코드는 [build_research_gold.py](src/build_research_gold.py)입니다. 파일의 metadata.json에서 출처와 검사 결과를 확인하세요.

공개 시각이 NULL인 과거 자료는 연구용입니다. 이 파일로 전처리와 비교 실험을 개발할 수 있지만 엄격한 시점 검증 완료 데이터라고 부르면 안 됩니다. 이후 Fabric Gold로 교체해도 컬럼 이름은 같습니다. ECOS를 포함한 입력 계약 수정이 모델 성능 승인을 뜻하지는 않습니다.

로컬 ECOS 비교는 18종목, 184개 평가 시점에서 수행했습니다. 평균 절대오차는 4.6578%p에서 4.6344%p로 약 0.5% 감소했지만, 삼성전자와 현대차 각 50% 포트폴리오는 오차가 증가했습니다. 이미 사용한 기간의 비교 실험이며 독립 블라인드 검증은 아닙니다.
