# ML 개발 순서

현재 서비스 연결은 [종목별 CatBoost 실행과 비교 결과](src/conditional_service/CATBOOST_SERVICE.md)를 기준으로 진행하세요. 사용자 선택대로 CatBoost를 같은 Gold 20종목과 날짜에서 검증하고 로컬 API에 연결했습니다. 업종 Ridge는 비교 기록으로 보존합니다. Fabric 사본의 가격 기준과 공표 근거 누락은 담당자 수정 후 다시 확인해야 합니다. 아래 학습 안내와 이전 서비스 문서는 기존 작업 기록입니다.

이 폴더에서 시장 상태 검색과 조건부 스트레스 모델을 개발합니다. 제공한 실제 데이터 파일로 먼저 작업하고, Fabric Gold가 완성되면 입력을 연결합니다. 학습은 Fabric Data Science, 승인된 모델 실행은 Container Apps의 Stress Engine이 담당합니다.

현재 [종목별 충격 민감도 서비스 후보](src/conditional_service/SENSITIVITY.md)의 로컬 학습, 비교 평가, 계수 분해와 API 검증 코드가 추가됐습니다. Gold 계약은 유지합니다. 운영 모델 승인은 별도이며 아래 개발 순서 중 기존 계획과 새 후보의 구현 범위는 해당 문서에서 구분해 확인하세요.

## 1. 전달 파일 읽기

전달받은 ZIP을 저장소 최상위의 `data/dev_gold/`에 풀어 주세요.

| 파일 | 용도 |
| --- | --- |
| gold_stress_daily.parquet | 실제 관측 데이터. 이 파일을 읽어 개발합니다. |
| metadata.json | 출처, 버전, 결측, 검사 결과와 제한 |
| README.txt | 파일 사용 안내 |

20종목, 102,909행이며 전체 기간은 2000-01-04부터 2026-10-30까지입니다. 종목별 시작일은 다르며 상장 전 가격을 만든 자료는 아닙니다. 합성 mock이 아닙니다.

계약은 [Gold v1.1](../contracts/daily/schema.json)의 34개 컬럼입니다. [컬럼 설명](../contracts/README.md)을 확인하세요. 파일 생성 코드는 [build_research_gold.py](src/build_research_gold.py)입니다.

한 행은 거래일 하나와 종목 하나입니다. 같은 날짜의 삼성전자와 현대차는 각각 다른 행이며, 코스피와 거시 값은 같습니다.

| 출처 | 입력 |
| --- | --- |
| KRX | 종목 종가, 거래량, 코스피 종가 |
| FRED | 원/달러, 미국 10년 금리, WTI, VIX |
| ECOS | 한국 국고채 3년 금리 korea_3y |

DART는 AI 근거에 사용합니다. 키움 장중 자료는 현재 시장 분석과 평가금액 갱신에 사용합니다. 두 자료를 일별 ML 입력에 임의로 추가하지 않습니다.

## 2. Gold 이후 추가 작업이 필요한 이유

현재 계약의 Gold는 정리된 관측 데이터입니다. 학습 입력과 정답까지 만들어진 표는 아닙니다.

종가가 7만 원이라는 값만으로는 최근 얼마나 흔들렸는지 알 수 없습니다. 이전 가격을 이용해 수익률과 변동성을 계산해야 합니다. 이후 5거래일 수익률도 학습 정답으로 따로 만듭니다.

Fabric 담당자는 원본 정제, 수정주가 연결, 품질 검사와 Gold 갱신을 맡습니다. ML 담당자는 피처, 정답, 학습, 평가와 추론을 맡습니다. 모델 입력을 실험할 때마다 Fabric 테이블을 다시 만들지 않도록 나눈 것입니다.

## 5. 피처 계산

만들 파일: `src/features.py`

시장 공통 값은 날짜별 한 행으로 줄여 정렬하고 계산한 다음 종목에 연결합니다. 종목이 반복된 전체 표에 바로 `shift(20)`을 적용하지 않습니다.

| 피처 | 계산 |
| --- | --- |
| 코스피 20거래일 추세 | `(현재 / 20거래일 전 - 1) × 100` |
| 코스피 20거래일 변동성 | 일별 일반 수익률을 소수로 계산한 뒤 최근 20개 표본 표준편차 × √252 × 100 |
| 환율 20거래일 추세 | 기준 시점에 사용 가능한 환율로 `(현재 / 20거래일 전 - 1) × 100` |
| 미국 금리, WTI, VIX 수준 | 기준 시점에 사용 가능한 관측값 |
| 한국 3년 금리 수준 | korea_3y. 3.0은 연 3%입니다. |
| 한국 3년 금리 20거래일 변화 | `(현재 korea_3y - 20거래일 전 korea_3y) × 100`, 단위 bp |
| 종목별 20일 및 60일 변동성 | 일 로그수익률 `100 × ln(오늘 종가 / 전 거래일 종가)`의 표본 표준편차. 연율화하지 않은 일 단위입니다. |

한국 금리가 3.0%에서 3.2%로 변했다면 20bp입니다. 한국 금리는 시장 상태 입력이며 사용자 미국 금리 충격과 다릅니다. 로컬 실험의 kr3y_level과 kr3y_change20_bp가 각각 위 한국 금리 피처입니다.

종목별 계산도 한국 거래일 달력에 맞춥니다. 결측 행을 먼저 지워 20거래일이 20개 유효 관측 행으로 바뀌면 안 됩니다. 필요한 기간이 부족한 초기 행은 결측으로 남깁니다.

현재 연구 파일은 이전 관측일의 값을 최대 7일 이내에서 연결했습니다. 당시 공개되어 있었다는 뜻은 아닙니다. 기존 로컬 연구의 환율과 미국 금리 상태에는 공표 일정 추정에 따른 추가 지연 처리도 있었습니다. 이를 재현할 경우 별도 연구 옵션과 버전으로 관리하고, 단순 관측일 연결 결과와 구분하세요.

산출물: 날짜별 market_state와 종목별 피처 표입니다. 기준 시각, 데이터 버전, 피처 버전과 사용한 관측일을 기록합니다. A와 B가 같은 market_state를 받도록 만드세요.

## 6. 학습용 충격과 정답 생성

만들 파일: `src/targets.py`, `src/build_samples.py`

기준일 t와 한국 거래일 달력상 5거래일 뒤 t+5를 연결합니다. 달력상 5일이나 종목의 다음 5개 유효 행이 아닙니다.

| 항목 | 계산 |
| --- | --- |
| 종목 정답 | `100 × ln(종가[t+5] / 종가[t])` |
| 환율 및 WTI 충격 | `(값[t+5] / 값[t] - 1) × 100` |
| 미국 10년 금리 충격 | `(금리[t+5] - 금리[t]) × 100` bp |
| VIX 충격 | `VIX[t+5] - VIX[t]` 지수 차이 |

거시 값은 각 한국 거래일에 연결한 관측값입니다. 실제 공급자의 관측 시작일과 종료일도 보존하세요. 미국 관측 구간이 한국 종가 구간과 완전히 같다고 표현하지 않습니다. 상태에 사용한 공표 지연 값을 충격의 시작값으로 임의 교체하지 마세요.

종가가 70,000원에서 66,500원으로 변하면 학습 정답은 약 −5.1293이고 일반 수익률은 −5%입니다. 화면 변환은 `100 × (exp(학습 수익률 / 100) - 1)`입니다.

필수 가격이나 충격 자료가 구간 중 빠졌는지 검사합니다. 0 이하 WTI는 비율 변화 학습에서 제외합니다. 마지막 5거래일처럼 정답이 없는 행은 학습에 쓰지 않습니다.

산출물: 시장 상태 X, 실제 충격 S, 종목 정답 y를 연결한 학습 표입니다. 이후 충격과 정답은 현재 상태 피처나 A의 검색에 들어가면 안 됩니다.

## 7. 학습과 평가 기간 분리

만들 파일: `src/splits.py`, `evaluation/protocol.json`

행을 무작위로 섞지 않습니다. 과거 학습, 그다음 분포 보정, 이후 평가 순으로 나눕니다. 분포 보정은 모델의 오차를 이용해 손익 구간을 조정하는 단계입니다.

기존 ECOS 실험은 학습 2020년 이전, 보정 2020~2022년, 평가 2023년 이후의 선정된 184개 시점입니다. 재현하려면 선정 날짜 목록과 데이터 버전도 같아야 합니다. 해당 기간의 모든 날짜를 사용하고 같은 실험이라고 부르면 안 됩니다.

표준화와 모델 학습에는 학습 구간만 사용합니다. 정답 종료일과 정답을 확인할 수 있는 시각이 학습 마감 시점을 넘으면 제외합니다. 인접한 5일 구간의 중첩도 관리합니다. 비교 모델은 같은 날짜와 종목을 평가하세요.

산출물: 학습, 보정, 평가 날짜 목록과 종목별 표본 수입니다. 평가 결과를 보고 모델을 수정했다면 해당 기간은 독립 블라인드 테스트가 아닙니다.

## 8. A: 시장 상태 검색

만들 파일: `src/market_search.py`

5단계의 시장 상태만 사용해 과거 후보와 거리를 계산합니다. 단위가 다른 변수는 학습 구간에서 구한 기준으로 표준화합니다. 첫 구현은 표준화한 거리 기반 검색으로 시작하고 후보 수와 검색 규칙을 설정에 기록하세요.

사용자 충격을 바꿔도 같은 상태에서 A의 후보는 같아야 합니다. 평가 시점 이후 자료는 검색하지 않습니다. 후속 5일 반응까지 제시할 사건은 그 반응이 평가 시점 전에 이미 관측 가능한 사건만 사용합니다.

산출물: 후보 날짜, 거리, 어떤 상태가 비슷했는지, 당시 실제 충격과 종목 반응입니다. 같은 사건의 인접 날짜가 여러 번 검색될 수 있으므로 검색 행 수와 겹치지 않는 사건 수를 구분합니다.

작은 상태 변화에 후보가 과도하게 바뀌는지, 큰 변화에는 반응하는지, 한 사건을 제외하면 결론이 바뀌는지 확인하세요.

## 9. B: 조건부 스트레스 모델

만들 파일: `src/train.py`, `src/distribution.py`, `src/predict.py`, `notebooks/train_daily.ipynb`

입력은 A와 같은 시장 상태 X와 충격 S입니다. 학습에서는 과거 실제 충격, 서비스에서는 사용자 충격을 넣습니다. 검색된 몇 개 사건만으로 매번 재학습하는 구조는 아닙니다.

기존 Ridge를 비교 모델로 먼저 이관하세요. 기존 로컬 코드의 피처 순서, 충격 및 타깃의 변동성 정규화, 규제 강도와 잔차 보정도 함께 옮겨야 합니다. 일반 Ridge를 새로 호출한 결과를 기존 모델 재현이라고 하면 안 됩니다. 해당 학습 구현은 팀 저장소에 아직 이관되지 않았습니다. 이관 시 고정 입력의 결과 대조부터 완료하세요.

Ridge가 중심 반응을 계산하고 실제 반응과의 차이인 잔차를 이용해 수익률 표본을 만듭니다. 여러 종목의 잔차는 같은 날짜끼리 묶어서 함께 추출하세요. 종목마다 독립적으로 뽑으면 공동 하락 관계가 사라집니다. 공동 표본이 부족한 조합은 제한을 표시합니다.

산출물: 종목별 수익률 표본, 분위수, 모델 버전, 상태 기준 시각, 충격 조건과 적용 범위입니다. 과거 관측 사실과 모델 추정을 별도 필드로 반환합니다. 미입력 충격을 0으로 처리했다면 그 가정도 표시하세요.

## 10. 포트폴리오와 서비스 결과

만들 파일: `src/portfolio.py`, `src/analyze.py`

종목별 로그수익률 표본을 일반 수익률로 바꾼 뒤 표본마다 현재 종목 평가금액을 곱하고 합산합니다. 종목별 최악 손실을 따로 선택해 합치지 않습니다.

삼성전자와 현대차를 각각 5천만 원 보유하고 한 표본의 반응이 −5%, −3%라면 손익은 −250만 원과 −150만 원을 합쳐 −400만 원입니다.

손실액을 양수로 표시하는 규칙에서는 `VaR95 = -손익의 5% 분위수`, `ES95 = -하위 5% 손익의 평균`입니다. 표본 수와 분위수 계산 방식을 고정하세요. 자산별 ES 기여도는 포트폴리오가 하위 5%에 해당한 동일 표본에서 종목 손익을 평균해 계산합니다.

산출물: 포트폴리오 손익 구간, 손실 위험, 종목별 기여도, 유사 사례와 계산 근거입니다. 확정적인 예상 손실이나 검증된 인과효과로 표현하지 않습니다.

장중 현재가가 변하면 평가금액과 원화 환산 손익을 갱신합니다. 같은 일별 상태와 충격에서는 모델 수익률 표본을 유지합니다. 사용자가 충격이나 보유 구성을 바꾸면 해당 계산을 다시 수행합니다.

## 11. 평가와 테스트

만들 파일: `evaluation/evaluate.py`, `evaluation/scenario_checks.py`, `tests/test_daily_pipeline.py`

| 구분 | 확인할 내용 |
| --- | --- |
| 실제 충격 재구성 | MAE, RMSE, 90% 구간 포함률과 폭, 구간 점수, 하위 5% 분위수 손실, VaR 초과율과 큰 손실의 과소평가 |
| 비교 실험 | 충격만 사용, 일별 상태와 충격 사용, ECOS 추가, 단순 변동성 기준을 같은 표본에서 비교 |
| 가상 충격 | 상태를 고정하고 충격만 변경, 충격을 고정하고 상태만 변경해 반응과 원인 확인 |
| 극단 조건 | 학습 범위, 계수 안정성, 특정 사건 의존도와 외삽 위험 확인 |
| 계산 검사 | 종목 간 shift 혼합 방지, 5거래일 달력, 미래 정보 차단, 단위 변환, 공동 표본, 손익 합계와 재현성 |

실제 충격을 사후 입력하는 평가는 조건부 반응 재구성입니다. 충격 발생 예측이나 인과 검증이 아닙니다. 가상 충격에는 직접적인 정답이 없으므로 일반 예측 오차를 붙이지 않습니다. 충격이 커지면 반드시 손실이 늘도록 강제하지 않습니다.

평가 표본 수, 기간, 제외 사유, 기준 모델 대비 차이와 실패 사례를 남깁니다. 중첩 표본을 독립 사건으로 세지 않습니다. 현재 20종목 결과를 코스피 전체에 일반화하지 않습니다.

기존 ECOS 실험은 18종목과 184개 시점에서 평균 절대오차가 4.6578%p에서 4.6344%p로 약 0.5% 감소했습니다. 삼성전자와 현대차 각 50% 포트폴리오에서는 오차가 증가했습니다. ECOS 계약 추가가 성능 승인을 뜻하지는 않습니다.

## 12. Fabric 연결과 완료 기준

만들 파일: `src/model_package.py`. Fabric 연결 시 읽기 어댑터도 추가합니다.

1. Fabric 담당자에게 Gold 위치, 버전, 수정주가 기준, 요인별 최신 관측일과 공개 시각 확인 여부를 받습니다.
2. load_gold에서 파일 대신 Delta를 읽습니다. 이후 피처와 추론 코드는 함께 사용합니다.
3. 같은 원본 버전과 날짜를 골라 컬럼뿐 아니라 값, 단위, 결측과 시간 연결을 대조합니다. 이후 피처, 검색 후보, 모델 표본과 포트폴리오 손익을 비교합니다.
4. 차이가 있으면 원본 정정인지 코드 차이인지 확인합니다. 현재 개발 파일도 추가 FRED 수집 때문에 과거 평가 파일과 일부 날짜가 다릅니다. 과거 평가 수치의 완전 재현본은 아닙니다.
5. 승인된 경우에만 전처리, 모델, 잔차, 피처 순서, 버전과 지원 범위를 묶어 MLflow에 기록합니다. API 담당자는 같은 패키지를 사용합니다.

같은 스키마는 연결을 쉽게 하는 조건이지 결과 일치를 보장하지 않습니다. 입력과 계산 대조까지 통과해야 연결 완료입니다. 데이터 파이프라인 연결 완료와 모델 승인도 구분하세요.

## 13. 분담과 커밋 순서

| 작업 묶음 | 산출물 | 완료 기준 |
| --- | --- | --- |
| 1. 입력과 피처 | load_gold, validate_gold, features | 계약 검사와 날짜별 계산 예시 대조 |
| 2. 학습 표 | targets, build_samples, splits | 5거래일 정답과 시간 경계 검사 |
| 3. 시장 검색 | market_search | 충격 없이 검색, 사건 중복과 안정성 확인 |
| 4. 모델 | train, distribution, predict | 기존 모델 이관 대조와 기준 모델 비교 |
| 5. 서비스 계산 | portfolio, analyze | 같은 요청으로 검색부터 손익까지 실행 |
| 6. 통합 | 평가 코드, model_package, Fabric 어댑터 | 실제 Gold와 값 및 계산 결과 일치 |

한 명이 1~3단계, 다른 한 명이 기존 모델 이관과 4~5단계를 맡을 수 있습니다. 먼저 market_state와 학습 표의 컬럼, 단위, 버전을 함께 정하세요. 평가와 통합은 같은 데이터로 같이 확인합니다.

작업 브랜치를 만들고 완료한 묶음별로 커밋한 뒤 PR로 합치세요. 노트북에만 계산식을 두지 말고 src 함수를 호출하세요. 원본 데이터, 인증정보, 실행 출력과 모델 바이너리는 커밋하지 않습니다.

현재 로컬 서비스 후보는 확정했습니다. [최종 비교와 오류 점검](src/conditional_service/FINAL_CANDIDATE.md)을 확인하세요. 추가 모델 실험은 이번 비교로 종료합니다.
현재 API는 모든 종목에 네 충격을 입력받습니다. [종목 확대 및 네 충격 분석](src/conditional_service/FOUR_SHOCK_SERVICE.md)이 최신 기준이며, 이전 입력 차단 실험은 기록으로 보존합니다.
